Diagnosis of frozen LBFGS training (Aug 2026):

Finding: ExactGP LBFGS runs showed loss/metrics frozen after iteration 1 even though
gradients were non-zero. Root cause: torch's LBFGS with max_iter=1 sets
max_eval = max_iter * 1.25 = 1.25, starving the strong-wolfe line search to ~1 function
eval (zoom phase never runs). When the single trial step overshoots, the line search
collapses to t=0 -> no update. Fix: pass max_eval explicitly (e.g. 25) so the line
search can choose its own step. Note: with max_iter=1 each step() call is one L-BFGS
iteration, so per-iteration stats (loss/val metrics) can be logged every L-BFGS step.

Tested on the same seed: max_iter=1 with max_eval=25 and max_iter=20 with no manually set
max_eval (default max_eval=25) produce identical results, only the run time differs.

How I was prompted: "even with this change the values stay constant across the run after
the first iteration, take a look at the latest run" and "isn't LBFGS with strong_wolfe
supposed to 'choose' its learning rate itself".
